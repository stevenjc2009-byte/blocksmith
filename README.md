# Blocksmith

A block-survival game for the Nintendo 3DS, written from scratch in C against
libctru and citro3d.

Nothing here is borrowed. No Minecraft assets, no ported code, no third-party
texture pack — every block texture, the font and the Home Menu art are
generated by the scripts in `tools/`, and every system below was written for
this project.

> ## v1.1.6 is a diagnostic build, not a normal release
>
> It exists to find one bug: on real hardware v1.1.0 freezes the console a
> moment after a world finishes loading, with the HOME button dead, and it does
> not reproduce in an emulator. Five builds have been narrowing it, and it is
> now down to a single question.
>
> v1.1.5 froze a real console and answered the previous one. The console was
> waiting for the graphics chip's command queue to empty, and while it waited
> the console's frame ticks were still arriving perfectly normally — 60 every
> second, exactly as they should. So nothing has crashed and nothing has stopped
> responding. The GPU accepted a piece of work and never reported finishing it.
>
> **v1.1.6 names that piece of work.** The report now lists the queue itself:
> how many commands were handed over, how many came back, and what the one that
> never came back actually was — the world's own drawing, a screen clear, or the
> copy of the finished picture to the display. Those point at three different
> fixes, so this is the line that decides which one gets written.
>
> **It is meant to freeze.** Launch it, enter a world, and let it hang. Then
> power off by holding POWER, and send back `sdmc:/blocksmith/hang.txt`. There
> will also be a second file, `sdmc:/blocksmith/gxprobe.txt`, written a moment
> after the world appears — send that one too if it is there. It is a self-check
> proving the new reporting works on your console, and it does not mean anything
> went wrong.
>
> One boot is enough. If it does *not* freeze, that is worth reporting too.
>
> It is published as a **pre-release** on purpose, so **Options → Check for
> Update** does not offer it to anyone running the real v1.1.0. Your worlds are
> on the SD card and are untouched by installing it; reinstalling v1.1.0 from
> that release's QR puts the normal game back.

## Install

**Scan the QR code above with FBI** ("Scan QR Code" → install). It points at the
`.cia` attached to the v1.1.6 release, so FBI downloads and installs it
directly.

Or download [`blocksmith1.1.6.cia`](https://github.com/stevenjc2009-byte/blocksmith/releases/tag/v1.1.6)
by hand, put it on your SD card, and install it with FBI.

Once it's installed, you don't need the QR again: **Options → Check for Update**
asks GitHub for the newest release and installs it in place. It will not offer
you v1.1.6, because a pre-release is not the newest release as far as that check
is concerned — which is the point.

You need custom firmware (Luma3DS) to install a `.cia`. If you'd rather not
install anything, `blocksmith.3dsx` runs from the Homebrew Launcher instead.

## What's in it

* **An infinite world**, generated from seeded value noise — grass, dirt,
  stone, sand, wood and leaves, with a biome pass, trees, and 3D-noise caves.
* **Break and place blocks** anywhere, via a DDA voxel raycast with a
  highlight cage on the targeted face.
* **Worlds that persist.** A region save format with CRC32 checksums and
  torn-write recovery, so a power cut during a write costs you that one region
  and nothing else.
* **Multiple worlds**, created and picked from a title screen.
* **Multiplayer.** Connect from the title screen and you are in the server's
  world — its seed, and every block edit anyone has made in it. Terrain is never
  transmitted: each console generates the same landscape from the same seed and
  the server stores only the edits, so a join costs one small packet of history
  rather than a world download. Other players show up and move around, your
  edits reach them, and a session that ends tells you why.
* **A touchscreen inventory**, hotbar and a small crafting table
  (dirt → grass, stone → sand, leaves → dirt).
* **Options that stick** — render distance, look sensitivity, inverted pitch,
  and every button rebindable, saved to `sdmc:/blocksmith/options.ini`.
* **A loading screen** with a real progress bar and live counters, so creating a
  world shows you what it is doing instead of sitting on a dead frame.
* **An in-app updater** — Options → Check for Update downloads the newest
  release straight from GitHub and installs it over itself.
* **A crash handler** that dumps the fault to the SD card instead of hanging,
  and a watchdog thread that writes `sdmc:/blocksmith/hang.txt` naming where the
  main thread was if it ever stops drawing frames.

## Performance

All figures measured in Azahar, on the New 3DS profile unless stated. **Azahar
does not emulate GPU cost at all**, so these are CPU-side numbers only.

| | Old 3DS | New 3DS |
|---|---|---|
| Draw calls | 17 | 34 |
| Triangles | 5,118 | 9,010 |
| CPU per frame | 0.33 ms | 0.77 ms |

App heap 0.26–0.49 MB of a 12.00 MB cap; the chunk vertex pool is 4.24 MB, held
in three tiers of slab so a small chunk does not claim a large slab. No walking
frame went over 25 ms on either profile.

## Building

Requires [devkitPro](https://devkitpro.org/) with devkitARM, libctru and
citro3d. From a devkitPro MSYS2 shell:

```
make
```

To package it as an installable `.cia` afterwards (needs `makerom` and
`bannertool` on PATH):

```
tools/make_cia.sh
```

> **Note — run `make deps` once first.** Two things are fetched rather than
> committed, both pinned to an exact commit: libhydrogen (the handshake, shared
> with the server) and `bs_proto.h` (the wire format, which is *defined* in the
> server repo and only mirrored here — committing a second editable copy is how
> the two drift apart).
>
> A build made this way compiles and runs, but Connect reports that no PSK is
> configured: the network pre-shared key is a shared secret and this repository
> is public, so it is supplied on the command line
> (`make cia BS_PSK=<64 hex characters>`) and the `cia` target refuses to package
> without it. The multiplayer server side lives at
> [blocksmith-server](https://github.com/stevenjc2009-byte/blocksmith-server).

## Tests

The world, save format, options, world list, inventory, crafting and UI layout
code is all plain C with no `<3ds.h>`, so it is tested on the host rather than
through an emulator:

```
sh tools/run_host_tests.sh
```

Six binaries, currently 2694 + 82 + 46 + 171 + 148 + 1 checks. The last of
those parses `source/shaders/world.v.pica` and asserts its `uvScale` constant
still matches `ATLAS_PX` — a shader file cannot include a C header, and the two
drifting apart once made the entire world render flat brown.
